## 2026-10-10 — Плата видна в DFU из WSL

- Поставил usbipd-win (Windows), usbutils и dfu-util (WSL).
- Разобрался по RM0383 §2.4, как ножки BOOT0/BOOT1 выбирают, откуда стартует STM32F411: Flash, system memory (загрузчик ST) или SRAM. Ножки защёлкиваются после выхода из сброса.
- Black Pill в DFU: `0483:df11`, проброшен в WSL через `usbipd attach --auto-attach`. `dfu-util -l` видит Internal Flash по `0x08000000`.
- **Проблема:** первый `dfu-util -l` завис намертво (процесс в состоянии `D`). Windows считала устройство отключённым (`Shared`), а Linux держал его подключённым: полуоткрытое соединение USB/IP. В `dmesg` знакомство с устройством застряло на `SetAddress`, рядом были ошибки сети WSL `getaddrinfo() failed`. Помогли detach через `/sys/devices/platform/vhci_hcd.0/detach` и повторный attach. Корневая причина не доказана.
- Без `sudo` dfu-util не может открыть устройство: нужно udev-правило.

**Дальше:** тулчейн `arm-none-eabi-gcc` и путь от сброса до `main()`.

## 2026-10-25 — Тулчейн и доступ к плате без sudo

- Поставил кросс-компилятор `arm-none-eabi-gcc` 14.2, newlib, openocd, gdb-multiarch и picocom. Кросс-компиляция: компилятор работает на x86-64 (host), а машинный код генерирует для Cortex-M4 (target).
- Написал udev-правило для загрузчика STM32 (`0483:df11`): права `0660`, группа `plugdev`. Теперь `dfu-util -l` работает без `sudo`.
- **Проблема:** `sudo` не запускается из терминала Claude Code, ему нужен настоящий TTY для пароля. Команды с sudo выполняю в отдельном окне WSL.
- Доехали BME280, MH-Z19B, логический анализатор и мультиметр. Ждут фазы 3.

**Дальше:** пустая прошивка — `main.c`, linker script и startup, путь от сброса до `main()`.

## 2026-10-26 — Карта памяти и что происходит после сброса

- Разобрал карту памяти STM32F411 (RM0383 §2.3): Flash с `0x0800_0000` (512 КБ), SRAM с `0x2000_0000` (128 КБ), периферия с `0x4000_0000`. Секторы Flash из вывода `dfu-util -l` (4×16 + 64 + 3×128 КБ) совпали с картой.
- После сброса Cortex-M4 читает по `0x0000_0000` (при BOOT0=0 это алиас Flash) два 32-битных слова: начальный SP и адрес `Reset_Handler`.
- Посчитал начальный SP: стек растёт вниз, значит SP = конец SRAM = `0x2000_0000 + 0x2_0000 = 0x2002_0000`.

**Дальше:** linker script — как сказать линкеру, где Flash и RAM и что положить в первые 8 байт.
